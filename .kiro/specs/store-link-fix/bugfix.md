# Bugfix Requirements Document

## Introduction

The mobile app's "View on Store" functionality fails for certain store links (Jeevee and Oliz), preventing users from viewing products on the original store websites. When users click the "View on Store" button for products from these stores, they encounter HTTP errors (403 Forbidden for Oliz, 404 Not Found for Jeevee) instead of successfully reaching the product page. This breaks the core comparison shopping experience, as users expect to navigate seamlessly to any store to complete purchases or view detailed product information.

The issue affects approximately 33% of store integrations (2 out of 6 tested stores), significantly impacting user trust and the app's value proposition as a comparison shopping platform.

## Bug Analysis

### Current Behavior (Defect)

**User Story:** As a user browsing products in the mobile app, I encounter errors when trying to view Jeevee and Oliz products on their original store websites, so that I am prevented from completing my purchase or viewing detailed product information.

#### Acceptance Criteria

1.1 WHEN a user clicks "View on Store" for a product where the platform field equals "jeevee" THEN the system SHALL open the product_url field value in the device's default browser

1.2 WHEN the system opens a Jeevee product URL constructed in the format `https://www.jeevee.com/products/{slug}-{template_id}` THEN the device browser SHALL receive an HTTP 404 Not Found response from the Jeevee server

1.3 WHEN the device browser receives an HTTP 404 Not Found response from a Jeevee product URL THEN the browser SHALL display an error page indicating the requested page was not found

1.4 WHEN a user clicks "View on Store" for an Oliz product stored with a URL matching the pattern `https://www.olizstore.com/product/{slug}` THEN the system SHALL attempt to open that URL in the device browser

1.5 WHEN the device browser attempts to load an Oliz product URL THEN the Oliz server SHALL return HTTP 403 Forbidden status code

1.6 WHEN the device browser receives HTTP 403 Forbidden from an Oliz product URL THEN the browser SHALL display an access denied error page

### Expected Behavior (Correct)

**User Story:** As a mobile app user, I want working "View on Store" links for all supported stores, so that I can seamlessly navigate to any store website to view detailed product information or complete my purchase.

#### Acceptance Criteria

2.1 WHEN a user clicks "View on Store" for a Jeevee product AND the product has an associated Jeevee URL stored in the system, THEN the system SHALL open the URL in an external browser or webview within 2 seconds of the click action

2.2 THE system SHALL validate that each Jeevee product URL begins with "https://jeevee.com.np/" OR "https://www.jeevee.com/" before attempting to open it

2.3 THE system SHALL consider URL loading successful IF the HTTP response status is 200 OR within the range 300-399 (redirects)

2.4 IF a user clicks "View on Store" for a product that does not have an associated Jeevee URL stored in the system, THEN the system SHALL display an error message indicating the product link is unavailable

2.5 IF the URL fails to load within 10 seconds OR returns an HTTP error status (400-599), THEN the system SHALL display an error message indicating the product page could not be loaded

2.6 WHEN an Oliz product URL is generated by the scraper, THEN the system SHALL construct the URL using the format `https://www.olizstore.com/product/{slug}` WHERE slug is the SEO-friendly identifier from Oliz's product API response

2.7 WHEN the Oliz scraper constructs a product URL, THEN the system SHALL validate that an HTTP HEAD request to the URL returns status 200 OR 3xx within 5 seconds before storing the URL

2.8 IF an Oliz product URL validation fails (returns 403, 404, 5xx, or times out after 5 seconds), THEN the system SHALL log the failure and attempt an alternative URL format OR mark the product URL as unavailable

2.9 WHEN a Jeevee product URL is generated by the scraper, THEN the system SHALL construct the URL using the format `https://www.jeevee.com/products/{slug}-{template_id}` WHERE slug is derived from the product's `seo_details.slug` field normalized to lowercase with non-alphanumeric characters replaced by hyphens and template_id is the value from the `product_template_id` field

2.10 IF the `seo_details.slug` field is missing or empty THEN the system SHALL generate the slug by normalizing the product's `label` field to lowercase and replacing all non-alphanumeric characters with single hyphens

2.11 WHEN the slug is normalized THEN the system SHALL remove leading and trailing hyphens from the resulting string

2.12 WHEN a Jeevee product URL is validated THEN the system SHALL verify that an HTTP GET request to the constructed URL returns a 2xx status code within 10 seconds

### Unchanged Behavior (Regression Prevention)

**User Story:** As a user, I want existing working store links to continue functioning correctly, so that my shopping experience is not degraded by the bug fix.

#### Acceptance Criteria

3.1 WHEN a user clicks "View on Store" for a Daraz product, THEN the system SHALL navigate to the Daraz product URL and receive an HTTP 200 response within 10 seconds

3.2 IF navigation to a Daraz product URL fails with a non-200 HTTP status code, THEN the system SHALL display an error message indicating the store page could not be opened

3.3 IF a user clicks "View on Store" for a Daraz product while the device has no network connectivity, THEN the system SHALL display an error message indicating network is required to view the store page

3.4 IF a Daraz product URL loading exceeds 10 seconds, THEN the system SHALL timeout the request and display an error message

3.5 WHEN a user clicks "View on Store" for a Hukut product, THEN the system SHALL navigate to the Hukut product URL and receive an HTTP 200 response within 10 seconds

3.6 IF navigation to a Hukut product URL fails with a non-200 HTTP status code, THEN the system SHALL display an error message indicating the store page could not be opened

3.7 IF a user clicks "View on Store" for a Hukut product while the device has no network connectivity, THEN the system SHALL display an error message indicating network is required to view the store page

3.8 WHEN a user clicks "View on Store" for a Neostore product, THEN the system SHALL open the product page in an in-app browser within 10 seconds AND receive HTTP status 200

3.9 WHEN a Neostore product page is opened via "View on Store", THEN the system SHALL verify the opened URL contains the Neostore domain "neostore.com"

3.10 IF network connectivity is unavailable WHEN a user clicks "View on Store" for a Neostore product, THEN the system SHALL display an error message indicating network unavailability

3.11 WHEN a user clicks "View on Store" for a Hardwarepasal product, THEN the system SHALL navigate to the product URL and receive an HTTP 200 response within 10 seconds

3.12 THE system SHALL NOT open Hardwarepasal product URLs that return HTTP 403, 404, or 5xx status codes

3.13 IF a Hardwarepasal product URL fails to load within 10 seconds, THEN the system SHALL display a timeout error message to the user

3.14 WHEN a product is stored in the database with a URL containing a valid scheme (http or https), a domain name, and total length not exceeding 2048 characters, THEN the system SHALL store that URL character-for-character without altering case, encoding, protocol, path, query parameters, or fragments

3.15 WHEN a stored product URL is retrieved from the database, THEN the system SHALL return the URL with identical character sequence, encoding, and structure as originally stored

3.16 WHEN a retrieved product URL is displayed to the user, THEN the system SHALL present the URL with identical character sequence as retrieved from the database

3.17 IF a product storage request contains a URL that lacks a scheme, exceeds 2048 characters, or contains only whitespace, THEN the system SHALL reject the storage request with an error message indicating URL validation failure

3.18 IF a product storage request contains a URL with a scheme other than http or https, THEN the system SHALL reject the storage request with an error message indicating unsupported URL scheme
